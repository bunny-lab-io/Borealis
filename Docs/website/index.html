Borealis


Borealis is a remote management and automation platform built around a Linux-hosted Engine, a Windows-first agent model, and a visual workflow layer, with broader Linux agent parity still in progress. I originally started it to consolidate the mix of RMM, automation, and orchestration tools I was using across my homelab and real-world environments into one cohesive platform.


A Note on Development Pace:

I'm the sole maintainer and still learning as I go, while working a full-time IT job. Progress is sporadic, and parts of the codebase get rebuilt when I discover better or more optimized approaches. Thank you for your patience with the slower cadence. Ko-Fi donations are always welcome and help keep me motivated to actively continue development of Borealis.

Device Inventory + Approvals

Inventory, site assignment, approval queues, RBAC-scoped targeting, and filterable device views are built into the core platform.

Remote Shell + VNC

WireGuard-backed remote shell supports PowerShell on Windows and Bash on Linux, with same-origin VNC remote desktop for Windows.

Visual Workflows

Create drag-and-drop workflows that combine logic, scripts, and automation actions in one canvas.

Engine-side Ansible

The Linux Engine can run scheduled Ansible jobs over Borealis-managed WireGuard, SSH, and WinRM paths.

Security + Trust

Aegis bootstrap and unlock, MFA, passkeys, signed payload delivery, short-lived tokens, and approval-gated enrollment are all part of the current trust model.

Remote Script Execution

Run PowerShell, Batch, and Bash where available in CURRENTUSER or NT AUTHORITY\SYSTEM contexts.

Quick Jobs + Scheduling

Run quick jobs immediately or schedule scripts, workflows, and Engine-side automation with retained history.

Watchdogs + Alerts

Watchdogs, device alerts, and per-device role health help surface drift and trigger remediation workflows.

Quick Start

Download Latest Release Download Unstable Build

To get started, download the latest release from GitHub. If you want to experiment with bleeding-edge development, you can download the latest repository ZIP. Simply extract the ZIP somewhere on your computer (e.g. C:\Borealis or /opt/Borealis) and follow the instructions below.

Linux Engine
./bootstrap.sh --EngineProduction ./bootstrap.sh --EngineDev # Later redeploys ./Borealis.sh --EngineProduction ./Borealis.sh --EngineDev
  • Production: https://<your-public-fqdn>
  • Development: https://<your-public-fqdn> via Traefik-backed Vite HMR

Use bootstrap.sh for first-run provisioning, then Borealis.sh for later local redeploys.

Fresh Install Login Flow

Fresh installs do not seed a default administrator anymore. Borealis first requires Aegis setup, then first-admin creation, before the normal login UI becomes available.

  • Step 1: Complete the Aegis bootstrap gate.
  • Step 2: Create the first administrator account.
  • Step 3: Sign in normally once bootstrap reaches the login-required state.
Windows Agent Install
./Borealis.ps1

Run in elevated PowerShell. Enrollment still requires operator approval in the queue.

Windows Agent Bootstrap
& ([ScriptBlock]::Create((Invoke-RestMethod "https://raw.githubusercontent.com/bunny-lab-io/Borealis/refs/heads/main/bootstrap.ps1"))) --agent

Downloads to C:\Borealis, stages files, and launches agent deployment.

Windows Agent (embedded server URL + enrollment code)
& ([ScriptBlock]::Create((Invoke-RestMethod "https://raw.githubusercontent.com/bunny-lab-io/Borealis/refs/heads/main/bootstrap.ps1"))) --agent --serverurl "https://borealis.example.com" --enrollmentcode "E925-448B-626D-D595-5A0F-FB24-B4D6-6983"
Embedded bootstrap example

Use when distributing non-interactive installs with a predefined server endpoint and site enrollment code.

Linux Agent Status

Linux agent binaries are not currently published as a supported install path. The docs still treat Linux agent parity as incomplete, so the supported Borealis deployment today is the Linux Engine with the Windows agent.

  • Current state: parity work remains in progress.
  • Today: use the Linux Engine on the server side and Windows agents for supported rollouts.
