# Release Notes

## In Progress - Agent Context Socket Consolidation
Borealis now routes both SYSTEM and current-user agent work through a single Engine-facing SYSTEM socket, using locally launched per-session helpers when interactive user execution is required, and the supported Windows deployment path no longer depends on a standalone Borealis current-user scheduled task. The Engine now carries explicit helper and session-targeting metadata so current-user work can be brokered deliberately instead of through a second Borealis identity, both bootstrap entrypoints now support friendly release-channel selection plus explicit branch overrides for deployment testing, the Windows bootstrapper now consumes those bootstrap-only flags correctly before handing control to `Borealis.ps1`, the operator docs now spell out that unmerged bootstrap behavior must be tested with the matching branch or commit bootstrap script instead of `main`, the Windows Agent runtime packager now stages the new session broker module so consolidated agents can actually start after deployment, stale legacy interactive health rows are now replaced and hidden so the Device Summary reflects the supported one-socket runtime instead of old current-user leftovers, the helper runtime now suppresses duplicate per-session relaunches while creating Windows helper pipes that the target user session can actually open, the broker now reports helper-backed CURRENTUSER listener state explicitly so healthy helper sessions no longer look ambiguous in the Device Summary dialog, the CURRENTUSER health dialog now lists which interactive user sessions actually have helpers loaded, and the helper tray experience now uses a dedicated bottom-right PySide6 popup with a cleaner edge-docked connection-health layout, a slightly larger and more readable visual scale, and a more reliable site/header, shell, click-away dismissal, and simplified header composition instead of the old right-click context menu.

- Added a SYSTEM-owned session broker and helper runtime in `Data/Agent/session_runtime.py` and `Data/Agent/agent.py` that launches helper processes into active or locked sessions, advertises helper-backed current-user capability to the Engine, aggregates helper results, and keeps current-user execution local to the host instead of opening a second Borealis socket.
- Updated current-user script execution so `role_ScriptExec_CURRENTUSER.py` can run inside helper mode, trust broker-verified payloads, and execute scripts directly in the helper process while `role_ScriptExec_SYSTEM.py` delegates current-user work through the broker and returns consolidated results through the SYSTEM socket.
- Removed the Windows `Borealis Agent (UserHelper)` scheduled task from install and maintenance flows in `Borealis.ps1`, `Data/Agent/agent_deployment.py`, and `Data/Agent/restart_agent_tasks.ps1`, leaving the SYSTEM startup task as the only supported Borealis scheduler entrypoint.
- Extended Engine-side dispatch contracts in quick jobs, scheduled jobs, workflows, and watchdog remediations to carry `target_context`, `session_target`, and `target_session_id`, defaulting current-user scheduled and automation work to `all_active_sessions` while preserving helper-aware routing compatibility in the socket registry.
- Enriched device and agent visibility by surfacing helper readiness in session inventory, collapsing helper-backed current-user capability onto the SYSTEM `/api/agents` record, and updating the workflow Agent node to treat helper-backed current-user execution as a capability of the SYSTEM-connected host instead of expecting a second Borealis socket.
- Hardened scheduler and workflow behavior by improving scheduled-job host-status aggregation, adding a fallback for activity-history inserts when adapters do not expose `lastrowid`, stabilizing retention-sensitive unit fixtures, and restoring compatibility for workflow management registration when `aegis_cipher_service` is omitted from lightweight adapters.
- Updated Borealis documentation across the runtime, architecture, scheduling, assemblies, security, device-management, API-reference, and UI pages to describe the supported one-socket SYSTEM broker model, helper-only interactive execution, and the new session-targeting contract.
- Added `--release-channel stable|unstable` plus `--repo-branch` support to `bootstrap.sh` and `bootstrap.ps1`, with `stable` resolving the latest numeric repository tag, `unstable` preserving the existing branch-tip bootstrap behavior, and explicit branch or ref overrides remaining available for targeted testing flows such as `optimization/agent-context-socket-consolidation`.
- Fixed the PowerShell bootstrap argument parser so bootstrap-only options such as `--release-channel`, `--repo-branch`, `--ref`, and Git cache overrides are consumed by `bootstrap.ps1` itself instead of being accidentally forwarded into `Borealis.ps1`.
- Clarified the Windows bootstrap examples in `Docs/getting-started.md` so branch-testing commands fetch `bootstrap.ps1` from the same branch being validated and explicitly warn that `main` cannot exercise unmerged bootstrap-only flags.
- Fixed Windows Agent runtime staging in `Borealis.ps1` so `session_runtime.py` is copied into `Agent\Borealis` alongside `agent.py`, preventing `ModuleNotFoundError: No module named 'session_runtime'` when the consolidated SYSTEM agent starts after install or update.
- Updated Engine role-health merging and the Device Summary UI so upgraded agents replace stale legacy `currentuser` role rows such as `macro` and `screenshot`, while the summary hides those unsupported interactive-only remnants and continues to show the supported helper-backed `Script Execution - CURRENTUSER` health state.
- Hardened the helper and tray runtime by using unique per-launch helper pipe names, downgrading listener-creation failures into session-scoped broker log entries instead of crashing reconcile loops, and switching tray snapshot writes to unique temporary filenames so concurrent or leftover current-user helpers do not fight over `currentuser_status.json.tmp`.
- Fixed the session-helper broker relaunch path so an in-flight per-session helper launch is treated as still warming up instead of spawning another tray process, while stale unconnected helper launches are explicitly replaced and terminated by PID before Borealis retries the session.
- Fixed Windows helper IPC creation by replacing the default named-pipe listener with a session-scoped secured pipe that grants the target user session access for the local helper handshake, while helper-mode tray refreshes now stay in-memory instead of trying to rewrite the hardened shared tray snapshot file on every timer tick.
- Updated helper-backed CURRENTUSER health reporting so the broker now publishes `execution_context` plus an explicit `listener_state`, showing `Registered` when helper-backed script execution is ready instead of falling back to `Unknown` in the Device Summary details view.
- Expanded the CURRENTUSER agent-health details so the Device Summary dialog now shows a readable per-session helper ledger such as `DOMAIN\\user (session) - Loaded Successfully`, with pending helpers called out separately when interactive sessions exist but are still warming up.
- Replaced the helper tray's legacy right-click context menu with a PySide6-backed bottom-right popup dashboard, added a shared `qt_compat.py` shim so the agent prefers PySide6 while keeping the asyncio/Qt bridge stable during transition, updated Windows runtime staging to ship that shim, and refreshed the agent runtime docs plus SBOM to reflect the new desktop UI stack.
- Polished the new helper tray popup so it clamps fully inside the active screen, enlarges the Borealis logo, collapses redundant host/build/agent-ID details into a clearer connection summary, surfaces the applied release channel, and replaces the old security and WireGuard summary cards with itemized connection checks plus a simplified action row.
- Refined the helper tray popup shell so it docks flush to the right edge and taskbar line without the old floating outline, removes the remaining connection and session chrome, renames the health rows to more explicit transport labels, and expands copied support details with the same itemized trust, WebSocket, VPN tunnel, and interactive-session health signals shown in the dialog.
- Renamed the healthy WireGuard tray status from `Ready` to `Connected` so the popup wording matches the tunnel state more naturally in both the visible connection-health section and copied support details.
- Simplified the healthy interactive-session tray status from `Loaded Successfully` to `Running` so the popup reads more cleanly while still signaling that the helper-backed current-user runtime is active.
- Moved the tray popup’s last-heartbeat and engine-host details out of the header and into the `Connection Health` card, where heartbeat now renders as an exact seconds value and the configured Engine host appears as a centered footer label.
- Added the device’s assigned site to the helper tray header so the popup now shows the Borealis-blue site name directly under the hostname, with the site cached from the normal Engine heartbeat response instead of requiring a separate lookup.
- Increased the helper tray popup’s overall scale with slightly wider geometry, larger typography, roomier card spacing, taller action buttons, and a modestly enlarged Borealis icon so the docked bottom-right UI is easier to read at a glance without changing its structure.
- Refined the tray shell again by switching away from the native popup window chrome, anchoring the dialog after show-time against the full screen width so it stops clipping off the right edge, renaming the WebSocket row to `Websocket Connection`, carrying `site_id` through tray state for subtitle fallback, and substantially enlarging the logo so the header fills its space more intentionally.
- Reworked the helper tray header and shell so the popup uses a stable base icon instead of the live tray badge for header rendering, reduces the final logo size while eliminating its startup size jump, enlarges the hostname and connection-health title, moves the engine URL into a subtitle under `Connection Health`, removes transient copy/log feedback text, and dismisses when focus leaves or the user clicks outside the popup instead of only when the tray icon is clicked again.
- Simplified the tray popup again by removing the Activity and Release Channel badges, narrowing the dialog, shrinking the logo and primary heading scales, moving the engine URL back under the hostname, and updating the neutral engine-trust wording to `Checking Trust...` so the header and connection section read more cleanly.
